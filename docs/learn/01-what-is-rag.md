## 1. 왜 LLM에 그냥 묻지 않나

### 왜 필요한가

LLM은 **모르는 걸 모른다고 말하지 않는다.** 그럴듯한 문장을 만드는 게 그 모델이
학습한 일이라서, 아는 게 없어도 문장은 나온다.

이 프로젝트가 정확히 그 문제 때문에 시작됐다. 개 훈련 분야에는 **폐기된 이론**이
인터넷에 널려 있다. 대표적인 게 "지배이론(dominance theory)" — 개가 문제 행동을
하는 건 서열이 위라고 생각해서이니 보호자가 우두머리임을 알려줘야 한다는 주장이다.

이건 학계에서 반박된 지 오래고, 미국 수의행동학회(AVSAB)가 공식 성명서까지 냈다.
그런데 LLM에게 그냥 물으면 인터넷에 많이 쓰여 있던 그 조언이 나온다.

### 그래서 RAG

**RAG = Retrieval-Augmented Generation = 검색으로 보강한 생성.**

시험에 비유하면 이렇다:

| | 방식 | 문제 |
|---|---|---|
| 그냥 LLM | **암기 시험** — 머리에 든 것만으로 답 | 잘못 외운 걸 자신 있게 씀 |
| RAG | **오픈북 시험** — 자료를 찾아보고 답 | 자료에 없으면 못 씀 (이게 장점) |

"자료에 없으면 못 쓴다"는 **핵심 기능**이다. 이 프로젝트에서
`coverage: none`(자료 없음)으로 답을 거절하는 기능이 있는 이유가 그것이다.

### 직접 확인

```bash
# LM Studio를 켜고, 서버를 띄운 뒤
curl -X POST localhost:8000/api/v1/chat \
  -H 'content-type: application/json' \
  -d '{"question":"강아지 중성화 수술 비용은 얼마나 하나요?"}'
```

### 내 데이터의 실제 값 (2026-08-14 실측)

| 질문 | coverage | 근거 |
|---|---|---|
| 강아지 중성화 수술 비용은 얼마나 하나요? | `none` | 0건 |
| 서울에서 제일 좋은 애견카페 알려줘 | `none` | 0건 |
| 사료는 어떤 브랜드 추천 좀 해주세요 | `none` | 0건 |

**전부 답을 거절한다.** 이 코퍼스에는 가격·지역·상품 정보가 없기 때문이다.
그냥 LLM이었다면 셋 다 술술 답했을 질문이다.

> ⚠️ **같은 질문이 매번 같은 결과를 주지는 않는다.** 이 문서를 쓰면서
> "고양이 화장실 모래는 어떤 걸 써야 하나요?"를 예시로 넣으려다 실패했다 —
> 평가셋에서는 오래 거절되던 질문인데 이날은 `partial`로 근거 1건을 붙였다.
>
> 이유는 **거절 판정을 LLM이 하기 때문**이다(위 5단계의 근거 선별). LLM은
> 같은 입력에도 매번 똑같이 답하지 않는다. 실제로 검색 점수는 네 번 다 0.506으로
> 동일한데 선별 결과만 0건 → 2건으로 뒤집힌 기록이 있다.
>
> **그래서 점수 1점 차이는 잡음으로 봐야 하고, 회귀를 의심하기 전에 여러 번
> 돌려봐야 한다.** 06장(평가 지표)에서 다시 다룬다.

### 그래서 뭘 정했나

이 프로젝트는 **기관·학술 자료만** 코퍼스에 넣는다. 유튜브·블로그를 빼는 건
저작권 문제도 있지만, 더 큰 이유는 **지배이론 같은 폐기된 훈련법이 섞이기 때문**이다.
오픈북 시험인데 교재가 틀렸으면 답도 틀린다.

## 2. 임베딩 — "비슷한 뜻이면 가까운 숫자"

### 왜 필요한가

오픈북 시험을 보려면 **자료에서 필요한 페이지를 찾아야** 한다. 그런데 어떻게 찾나?

단어가 겹치는 걸로 찾으면(= 옛날 검색) 이런 게 안 된다:

- 질문: "강아지가 자꾸 물어요"
- 자료: "puppy mouthing and bite inhibition"

겹치는 단어가 **하나도 없다.** 언어도 다르고 표현도 다르다. 그런데 같은 얘기다.

### 임베딩이란

**문장을 숫자 목록으로 바꾸는 것.** 이 프로젝트는 `bge-m3`라는 모델을 쓰고,
문장 하나가 **숫자 1,024개**가 된다.

```
"강아지가 자꾸 물어요"  →  [0.021, -0.118, 0.077, ... ] ← 1,024개
"puppy mouthing"       →  [0.019, -0.121, 0.081, ... ] ← 1,024개
                             ↑ 비슷한 숫자가 나온다
```

핵심은 **뜻이 비슷하면 숫자도 비슷해지도록 훈련된 모델**이라는 것이다.
그래서 언어가 달라도, 단어가 하나도 안 겹쳐도 찾을 수 있다.

숫자 두 묶음이 얼마나 비슷한지는 **코사인 유사도**로 잰다. 1에 가까울수록 비슷하고,
0에 가까우면 무관하다.

### 직접 확인 — 실제로 벌어졌던 일

이 프로젝트에 기록된 실측값이다 (`app/services/query_rewrite.py` 맨 위 주석):

질문: **"복종 자세를 강제로 1~2분 유지시켜 서열을 알려줘야 한다"**

| 검색어 | 유사도 | 1등으로 나온 문서 |
|---|---|---|
| 한국어 원문 그대로 | 0.552 | Introduction to Desensitization… (**무관**) |
| 영어로 바꿔서 | **0.724** | AVSAB 지배이론 성명서 ✔ (**정확히 반박 자료**) |

### 그래서 뭘 정했나

**검색 전에 한국어 질문을 영어로 바꾸는 단계(질의 재작성)를 넣었다.**
코퍼스가 전부 영어라서다.

여기서 배울 게 하나 더 있다. bge-m3는 "교차언어 모델"이라 한국어로도 영어 문서를
찾는다고 알려져 있다. 실제로 **주제**는 넘나든다 — "짖어요" → barking은 잘 찾았다.
그런데 **기법 명칭**은 못 넘었다. `alpha roll`, `pinning` 같은 전문 용어가 그렇다.

> **교훈: "이 모델은 교차언어 지원"이라는 문장을 믿지 말고 내 데이터로 재라.**
> 이게 08장(임베딩 모델 선정)에서 할 일이다.

## 3. 질문 하나가 답이 되기까지 — 실제 코드 6단계

`app/services/rag_service.py`의 `answer()` 함수가 정확히 이 순서다.

```
사용자: "강아지가 초인종 소리에 계속 짖어요"
   │
   ├─1─ 질의 재작성      query_rewrite.py    한국어 → 영어 검색어
   │                                          "dog barking at doorbell, alarm barking"
   ├─2─ 임베딩           embeddings/         검색어 → 숫자 1,024개
   │                     huggingface.py
   ├─3─ 벡터 검색        vectorstore/        청크 11,354개 중 가까운 것 20개
   │                     pgvector.py           (top_k 5개 × 4배로 넉넉히)
   ├─4─ 재랭킹           vectorstore/        가산점 + 한 문서 편중 방지 → 5개
   │                     ranking.py
   ├─5─ 근거 선별        evidence_select.py  LLM에게 "이거 진짜 관련 있냐" 묻기
   │                                          → 관련 없으면 버림 (0개일 수도)
   └─6─ 답변 생성        rag_service.py      남은 근거로만 답 만들기
   │
답변 + 근거 출처 목록
```

### 각 단계를 왜 넣었는지

**1) 질의 재작성** — 위에서 본 그 이유. 실패해도 검색을 막지 않는다(원문으로 검색).

**2) 임베딩** — 검색어도 문서와 **같은 모델**로 바꿔야 한다. 자와 자가 달라서는
비교가 안 된다.

**3) 벡터 검색** — 11,354개를 전부 비교하면 느리므로 **HNSW 인덱스**로 근사해서
빠르게 찾는다. "대충 가까운 것들"을 아주 빠르게 찾는 자료구조다.

**4) 재랭킹** — 유사도만으로 줄 세우면 문제가 있다. 이 코퍼스는 청크의 96%가 논문이라
"어떻게 해요?"라고 물으면 실행 절차 대신 연구 결과가 올라온다. 그래서 실무
가이드에 소폭 가산점(+0.03)을 준다.

> ⚠️ **부스트는 아주 작아야 한다.** 근거 있는 질문(0.714)과 주제 공백(0.673)의 차이가
> 0.04밖에 안 된다. 부스트가 그보다 크면 **무관한 가이드가 정확한 논문을 밀어낸다.**
> 가산점은 동점자 처리(타이브레이커)지 검색 신호가 아니다.

**5) 근거 선별** — 이게 이 프로젝트에서 체감 품질을 가장 크게 바꾼 단계다.
왜냐하면 **검색은 항상 5개를 돌려주기 때문이다.** 코퍼스에 없는 주제를 물어도
"가장 덜 무관한" 5개를 준다. 그걸 그대로 LLM에 주면 없는 얘기로 답을 만든다.

그래서 LLM에게 한 번 더 묻는다: "이 청크가 이 질문에 실제로 답하나?"
→ 아니면 버린다 → 0개가 되면 "자료 없음"으로 거절한다.

**6) 답변 생성** — 남은 근거만 프롬프트에 넣는다.

### 직접 확인

```bash
uv run uvicorn app.main:app --reload
# 다른 터미널에서
curl -X POST localhost:8000/api/v1/chat -H 'content-type: application/json' \
  -d '{"question":"강아지가 초인종 소리에 계속 짖어요"}'
```

응답의 `coverage` 필드가 5단계의 결과다:

| 값 | 뜻 |
|---|---|
| `full` | 검색된 근거가 전부 관련 있음 |
| `partial` | 일부만 관련 있음 |
| `needs_detail` | 개 질문은 맞는데 정보가 부족 → 되묻기 |
| `none` | 관련 근거 없음 → 거절 |

## 4. 왜 점수 임계값으로 "자료 없음"을 판별하지 않나

이게 이 프로젝트에서 실제로 겪고 배운 것이라 짚고 간다.

"유사도가 0.65 미만이면 자료 없음으로 하자"가 가장 먼저 떠오르는 방법이다.
**측정해보니 안 된다.**

| | 실측 |
|---|---|
| 근거가 **있는** 질문의 유사도 **최솟값** | 0.686 |
| 주제가 **없는** 질문의 유사도 **최댓값** | 0.693 |

**겹친다.** 어떤 임계값을 골라도 한쪽이 틀린다. bge-m3의 한국어→영어 유사도는
값이 좁은 범위에 몰려 있어서(dynamic range가 좁다) 그렇다.

그래서 **LLM에게 관련성을 묻는 방식**(5단계)으로 갔고, 범위 밖 질문
통과율이 0/4 → 4/4로 바뀌었다.

> **교훈: 그럴듯한 규칙을 넣기 전에 분포를 그려보라.** 이게 03장(EDA)에서 할 일이다.

## 5. RAG 말고 그냥 웹 검색을 붙이면 안 되나

멘토가 짚어준 선택지다. LLM에게 웹 검색 도구를 쥐여주고 그때그때 찾게 하는 방법.

| | RAG (미리 수집) | 웹서치 에이전트 |
|---|---|---|
| 구현 난이도 | 높음 (수집·청킹·임베딩·DB) | **낮음** (API 하나 붙이면 끝) |
| 속도 | **빠름** (로컬 벡터 검색 수십 ms) | 느림 (매번 웹 왕복) |
| 자료 품질 | **통제 가능** (기관 자료만 넣음) | 통제 불가 (검색 결과 나름) |
| 자료 가공 | **미리 정제·분류 가능** | 그때그때 원문 |
| 최신성 | 수집 시점에 고정 | **항상 최신** |

**이 프로젝트가 RAG를 고른 이유:** 자료 품질 통제가 핵심 요구사항이라서다.
지배이론이 섞이면 안 되는데, 웹 검색은 그걸 막을 방법이 없다.

다만 정직하게 말하면 **연습 목적도 크다.** 실무에서는 둘을 섞는 경우가 많다 —
핵심 지식은 RAG로, 최신 정보는 웹서치로.

---

## 요점 3줄

1. **RAG는 오픈북 시험이다.** LLM이 지어내는 걸 막으려고 자료를 찾아서 준다.
   그래서 "자료에 없으면 거절"이 이 시스템의 기능이다.
2. **임베딩은 뜻을 숫자로 바꾼 것이고**, 뜻이 비슷하면 숫자도 가까워서 언어가 달라도
   찾을 수 있다. 단, "교차언어 지원"을 믿지 말고 내 데이터로 재야 한다 (0.552 → 0.724).
3. **검색은 항상 결과를 돌려준다.** 그래서 "관련 있냐"를 한 번 더 판정하는 단계가
   없으면, 코퍼스에 없는 주제에도 그럴듯한 답을 만든다.

2. 검색 4단계(재랭킹)에서 실무 가이드에 주는 가산점이 왜 +0.03처럼 작아야 하나?
   +0.3이면 무슨 일이 생기나?
3. 질의 재작성이 실패하면(LM Studio가 꺼져 있으면) 시스템은 어떻게 되나?
   왜 그렇게 만들었나?
